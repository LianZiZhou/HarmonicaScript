- DECISION: .NET 10 (LTS to 2028-11-14) with Avalonia 11.3.21, not Avalonia 12.1.2 — because both installed SDKs die 2026-11-10 so net10 is forced, while Avalonia 12 has no free DevTools (Avalonia.Diagnostics tops out at 11.3.21, confirmed), has deliberate breaking changes that invalidate essentially every tutorial and Chinese blog post, and has a live headless-test bug; 11.3.21 ships a net8.0 asset that resolves cleanly on net10.0, so the runtime decision is independent of the UI version.
- DECISION: do not reference Avalonia.Headless at all and write no automated UI tests in v1 — because it is the single dependency that would couple the whole test suite's xunit version to the UI version (11.x wants xunit v2 while the core suites use xunit.v3 4.0.0), and correctness lives in headless core tests, not in six interactive controls.
- DECISION: DryWetMidi 8.0.3 is a FILE PARSER ONLY with ExcludeAssets="build" — no Playback, no IOutputDevice, no Multimedia namespace, no HighPrecisionTickGenerator — because a live Playback object generates the schedule at run time, which would make Branch A's schedule and Branch B's exported schedule come from different code and silently diverge, the exact failure the layered architecture exists to prevent; seek is a binary search, speed is a recompile in single-digit ms, and pause is stop+ReleaseAll+reseek, which every source recommends anyway.
- DECISION: do not hand-roll the SMF parser — because DryWetMidi's tolerant ReadingSettings, Sanitize, GB18030 decoding and multi-tempo TempoMap are thousands of lines of hard-won correctness on exactly the malformed community files this project targets (KeySignature scale=255 broke the incumbent's loader until v1.0.5), and ExcludeAssets="build" already solves the native-blob complaint in one attribute.
- DECISION: the IR time unit is absolute int32 milliseconds, not microseconds — because every consumer without exception is integer ms (Razer <Delay>, Bloody 'Delay n ms', Logitech Sleep, AHK, G HUB durationMs), so rounding exactly once in a named pass is what keeps Branch A and Branch B bit-identical; absolute rather than delta storage bounds the rounding error at 0.5 ms with no accumulation, and the residual carry is needed only inside the export Deltaise pass. Microseconds in the IR would buy sub-ms precision no consumer can express while making every golden file noisier.
- DECISION: the IR carries no BatchId, no Label and no Value — batching is derived from equal TimeMs (a stored id is a second source of truth that can disagree), NoteId indexes back to the score for labels, and this instrument has three buttons with no wheel and no cursor movement, ever.
- DECISION: canonical key identity is the USB HID Usage ID (page 0x07) with PS/2 Set-1 plus an extended flag as a mandatory second column in keytable.json; mouse buttons are a small enum in SendInput order, not HID usages — because Bloody .amc and Redragon .MSMACRO literally store decimal HID usages so for them it is a cast rather than a translation, HID is positional and therefore layout- and IME-independent which matters for Chinese users, and Set-1 is mandatory because SendInput needs KEYEVENTF_SCANCODE and the verified Razer Synapse 3 macro stores Set-1 make codes. Mouse buttons get an enum because every vendor numbers them differently anyway.
- DECISION: the modifier state space is DERIVED at profile load from IReadOnlyList<ModifierSpec> plus exclusion groups plus MaxSimultaneousModifiers, and the DP loops 0..StateCount-1 — because hard-coding ModState(sbyte Shift, bool Sharp) with three named properties and a single global ModifierBehavior makes the plan's own load-bearing claim ('a game patch is a JSON edit') false for the most likely calibration outcome (per-modifier latching), and the plan's own figures show the perf argument is irrelevant. The 6-state analysis stays as documentation and as a pinned fixture test on df.harmonica.v1.json, not as the type system.
- DECISION: the generic profile validator asserts only DERIVED invariants (within-state injectivity, no interior coverage gaps, popcount sum, bindings resolve); the numbers 48, {1:30,2:6,3:2}, {-7,1,5,13,17,24} and {0,12} live in a fixture test pinned to one profile file — because those are properties of df.harmonica.v1 only, and hard-asserting them in the loader means the day the game patches to a 9-key row the correct user action ('edit the JSON') instead red-lines the whole test suite.
- DECISION: the transposition objective is TIERED LEXICOGRAPHIC (hardInfeasible count → musicalLoss ppm with a 0.5% epsilon → keyDistance → mechanical cost), not a weighted sum — because a weighted sum lets mechanical crumbs decide the key (a judge showed a 0.058 mechanical saving beating a 0.0125 key-fidelity term, silently detuning a piece by a semitone), lets hard infeasibility get ten times cheaper as a song gets longer when normalised by N, and needs two mutually inconsistent tie windows. Tiering fixes all three at once and makes 'transpose −1 with sharp always on' lose at tier 3 before mechanics is ever consulted.
- DECISION: cost modifier TRANSITIONS plus a per-second duty term charged over the INTER-ONSET span, never per-note occurrence and never over the note's own duration — because an all-sharp piece physically costs one middle-mouse press and one release, and because the duty must equal the hold time the maximal-run lowering actually produces (which includes intervening rests) or the DP minimises a quantity the emitter does not produce. octaveDown carries a 3x duty weight because LEFT MOUSE IS FIRE in this game.
- DECISION: no transposition prefilter — evaluate every exact-range candidate — because the prefilter saves nothing (8.6M cheap integer edge evaluations is low tens of milliseconds), prunes on the flat axis (out-of-range) while the spiky axis (modifier churn) decides the answer, mispriced the default FoldThenDrop policy by up to 20x on precisely the near-miss candidates most likely to be optimal, and introduced a 'best 25 with ties' determinism hole.
- DECISION: the DP's availSil is PESSIMISTIC — max(0, interOnset − NoteHoldMinMs), clamped, excluding the scheduler's shift budget — so any edge the DP believes feasible is realisable by truncating the previous note alone, a purely local operation that cannot cascade. This makes the plan sound in ONE pass and deletes SolverIterations=2 entirely, replacing a hoped-for empirical convergence result with a proof.
- DECISION: the deficit billed to the modifier plan is MARGINAL — reqSil(a,b) minus the best achievable reqSil over all legal state pairs for that note pair — because otherwise pure note-density infeasibility (15 ms inter-onsets against a 20 ms hold floor) is charged to the modifier plan and then amplified at 300k µu/ms, biasing spelling and transposition on exactly the dense passages that matter. Density infeasibility is reported separately as DensityDeficitCount.
- DECISION: all optimiser costs are int64 micro-units with no floats anywhere — because exact integer comparison makes the brute-force equivalence test non-flaky (a DP accumulating incrementally and a brute force summing whole paths will disagree in the last bits when per-ms and per-second scalings mix), makes tie-breaking deterministic, and makes golden files stable.
- DECISION: seam alternation is NOT a feature, is not claimed, and has no milestone gate — because within a fixed modifier state at most one key renders any offset (I verified this), so every alternative spelling of a repeated note costs a modifier transition; under the shipped default profile alternating (20+max(20,12)=40 ms) is actually WORSE than retriggering (20+12=32 ms). The DP will find it in the rare case it helps, and that is all.
- DECISION: the reduction passes are a bounded FIXPOINT GROUP (repeat until unchanged, max 4) and legalisation runs INSIDE the candidate loop before the DP — because smoothMelody and dropShort remove notes that reopen gaps monophony had closed, leaving predecessors artificially staccato against silence and mis-pricing the DP's edges, and because folding a note changes its band and therefore the state sequence, so folding after the DP invalidates the plan it just proved optimal.
- DECISION: smoothMelody PROMOTES the next-highest retained chord sibling before dropping, at ≥12 semitones above both neighbours and <90 ms — because the correct melody note is already sitting in ChordSiblingSourceIndices and the pass would otherwise punch a hole where it lives; and the 150 ms FoldRepeatedNotes pass is CUT entirely, because it would flatten every repeated sixteenth at ≤100 BPM across the pop/vocal files that are the modal use case and is redundant with the ladder's merge rung.
- DECISION: chord collapse uses a 45 ms window applied in MUSICAL time before speed scaling, and the collapsed group takes the EARLIEST onset — because it is a notational tolerance not a physical one (at 2x speed a 30 ms run would be misread as a chord), 25 ms misses DAW-humanised and lightly-rolled chords that BMP deliberately spaces at 50 ms, and 'keep highest' on a rolled chord otherwise lands the melody systematically late by the roll duration.
- DECISION: minSurvivingDurationMs is DERIVED as noteHoldMinMs + keyChangeGapMs — because the winner's max(45, noteHoldMin+5) evaluated to 45 under both shipped profiles, making the 'derived, not independently configurable' claim vacuous; this version gives 40 under df.reference and 65 under df.conservative, which is the real distinction.
- DECISION: the shipped default timing profile is df.reference — the reference tool's actual in-anger constants (12/8/16/20/20/10/25/25, breath rest on) — not the invented conservative set, with df.conservative one click away and named by the 'notes are being dropped' diagnostic — because one developer's tuning against the real game beats three research agents' inventions even though neither is a measurement, and the invented set's 15.4 nps ceiling versus the reference's ~30 would make the very first side-by-side against the incumbent on the same MIDI drop more notes and sound more staccato. Every value still carries a Provenance badge and four of them honestly read 'invented'.
- DECISION: breath rests default ON at the reference tool's 90 ms after 8 s of continuous sound — because it is the ONE guard a shipping tool added against an actually-observed in-game failure (判定粘连), and defaulting it off contradicts the fail-safe principle the plan otherwise argues.
- DECISION: hold caps are a COMPILE-TIME property of the InputTimeline (maxKeyHoldMs 4000, maxModifierHoldMs 6000, split at a rest where possible and the sounding note split with it), not a scheduler behaviour — because a scheduler-level cap mutates the stream below the validator so the events injected are not the events that were golden-filed, validated and simulated; because after a hard kill nothing re-runs so the cap bounds nothing; and because a compile-time invariant holds identically for an exported macro we do not control at run time. The real crash recovery is the release-all batch at session START, and the plan says so plainly.
- DECISION: TimelineValidator is a LOGICAL STATE MACHINE over the lowering's semantics, and it asserts modifier lead times before dependent NoteDowns — because event-pairing invariants are hold-shaped and a toggle-lowered timeline that leaves 半音 latched on in-game satisfies every one of them, and because without a lead-time check a timeline that arms a modifier at the identical TimeMs as the strike round-trips green while being exactly the 'note sounds a semitone wrong' bug the round-trip exists to catch.
- DECISION: InstrumentSimulator computes pitch from the profile's DegreeSemitones and ModifierSpec directly, NEVER from EmissionTable, and models pitch as a STEP FUNCTION over time asserted constant across each note's [down, up) span — because consulting the table would let a table bug cancel out on both sides of the round trip, and onset-only sampling is blind to the ModifiersRepitchSustainedNotes=true failure mode the flag exists to guard against.
- DECISION: the round-trip test also asserts the NON-CIRCULAR property — EffectiveMidiNote == SourceMidiNote + chosenTranspose for every note not flagged OctaveFolded/Dropped/ChordSibling — because comparing Simulate(timeline) against EffectiveMidiNote alone is a round trip through the same formula on both sides and cannot catch a wrong band or degree chosen by the planner.
- DECISION: ship a plain asInvoker manifest, never elevate by default, and never OpenProcess the game to read its integrity level — because standing elevation is a documented detection heuristic and a PRC-law aggravating factor while cross-process opening is the one behaviour ACE advertises intercepting; instead report our own elevation, run the Notepad delivery test, and offer 'restart as administrator' only from inside the wizard. Critically, a GREEN Notepad test does NOT clear the UIPI rung, because Notepad is medium integrity.
- DECISION: the shipped application makes no outbound network connection, ever — no telemetry, no update check, no crash reporting, no profile fetch — and Velopack is cut — because 'no network anything' is a property a user or a Chinese AV vendor can verify with a firewall in ten seconds, whereas an auto-updater fetching executables is precisely what makes a benign tool look malicious. Policy.Tests enforces it with Mono.Cecil over FIRST-PARTY assembly IL only, and the README states honestly that this is a first-party check rather than a runtime guarantee.
- DECISION: PublishAot=false and PublishTrimmed=false on every artefact, but AOT-clean discipline from commit one — because NativeAOT cannot cross-compile macOS→Windows at all, which would hard-bind the release pipeline to hardware the developer does not have, while ordinary IL self-contained single-file publishing DOES cross-compile and is exactly what lets win-x64 releases be cut from the Mac. EnableCompressionInSingleFile is also false, because compression is a top AV false-positive trigger.
- DECISION: do not take a dependency on SharpHook — because its bundled native libuiohook ships GPL-3.0/LGPL-3.0 and would attach relinking obligations to an MIT distribution; we need eleven keys on one OS and raw SendInput via CsWin32 is ~120 lines with exact control of KEYEVENTF_SCANCODE and batching.
- DECISION: the AutoHotkey v2 exporter ships BEFORE the Windows SendInput backend, in the first public release — because it reaches the game through a mature injection engine thousands of people have already validated, so it is Branch A with the developer's unverifiable surface removed, it severs the dependency in which the project's ability to release anything is gated on Windows hardware that does not exist, and it starts returning real in-game measurements before any weight is frozen.
- DECISION: use the free windows-2025 GitHub runner aggressively — execute the macOS-cross-published win-x64 exe, drive SendInput into a real Win32 window and assert the characters arrive, execute the generated .ahk with Send stubbed to a log and diff it against the InputTimeline, and measure real scheduler p99 deadline error — because it is the single cheapest way to shrink the unverifiable surface under a no-Windows constraint and it collapses roughly 70% of the Windows backend from 'hardware-blocked' to 'green check on every commit'.
- DECISION: drop the 'a reader for every writer, round-trip equality substitutes for the vendor software' mandate — because writer and reader share one mental model, so the three failure classes it is sold for (Razer <State> polarity, delay units, delta-vs-absolute) all round-trip perfectly while the file is wrong, which raises confidence in an unverifiable surface for no evidential reason. Readers are written only where the format is self-describing and has an independent consumer (hscore.json/csv, reduced .mid, ahk); real vendor samples become decode fixtures with hand-written expected timelines instead.
- DECISION: no exporter template DSL and no drop-in exporter plugin folder — because it would grant an exemption from all three validation techniques to precisely the exporters nobody has ever seen, invent a mini-language with no error-reporting design, add a load-arbitrary-config-from-a-writable-directory vector to a tool already expecting AV heuristics, and solve the wrong bottleneck (new vendors are blocked on sample acquisition, not authoring speed). - DECISION: golden exporter BYTES for six deliberately chosen fixtures, not the full fixtures x exporters cross product; golden the LOWERED EVENT LIST for every fixture instead — because 400+ artefacts and tens of megabytes of generated XML is the suite someone blanket-accepts or deletes at month six, and a serialiser bug is format-wide rather than fixture-specific so the six still catch 'I fixed Logitech and broke Razer'.
- DECISION: commit 25-30 public-domain MIDI fixtures plus a procedural fixture GENERATOR (code + seeds) covering chromatic runs, band-seam crossings, 4-second notes, dense sixteenths and forced exclusive swaps; all golden gates run on the committed set only — because gating five milestones on 'all 50' when 44 of them are third-party copyright means the backbone lives on one laptop, an outside contributor to a public open-source repo cannot reproduce a golden diff, and the provenance URLs rot within a year.
- DECISION: out-of-range default is FoldThenDrop (drop if <120 ms, else fold by at most one octave with a contour guard, else drop), clamp-to-edge is not a default, and the 4x asymmetric penalty for dropping HIGH notes lives in the transposition objective's tier 2 rather than in the per-note policy — because folding beyond one octave collapses wide-range material, clamping breaks pitch class and produces unison plateaus that read as a stuck note, and putting the asymmetry per-note conflates 'which transposition' with 'what to do about the residue'.
- DECISION: pass IDs are stable semantic strings with no ordinal, and ConversionReport is a PROJECTION over the PassCounter bag rather than 40 parallel typed fields — because inserting one pass in v1.1 would otherwise churn every golden report (swamping the rule that a weight change must show as a justified diff), and because two golden-snapshotted sources of truth for DroppedTooShort/tooShortDropped are guaranteed to diverge.
