Avalonia **11.3.21** on net10.0, `CommunityToolkit.Mvvm 8.4.2`, `x:CompileBindings="True"` project-wide, MIT `Avalonia.Controls.DataGrid`, `Avalonia.Diagnostics` for the visual tree, `HotAvalonia 3.1.4` for XAML hot reload. No paid component, no `Avalonia.Headless`. ViewModels are plain testable objects; the UI gets a manual screenshot checklist.

**i18n, done once.** Neutral `Resources.resx` in **English** + `Resources.zh-Hans.resx` (not zh-CN — the fallback chain `zh-CN → zh-Hans → zh → neutral` serves CN/SG/MY from one file). A ~40-line `Loc : ObservableObject` singleton with a string indexer and `SetCulture()` raising `OnPropertyChanged("Item[]")`, bound as `{Binding [Play_Start], Source={x:Static i18n:Loc.Instance}}` — Avalonia's own docs state `{x:Static}` bindings do **not** refresh on culture change. `<InvariantGlobalization>false</InvariantGlobalization>`, `<SatelliteResourceLanguages>en;zh-Hans</SatelliteResourceLanguages>`. **The core is never localised**: it returns `DiagnosticCode` enums with numeric args; the GUI maps codes to resx. A 10-line test asserts every neutral key exists in zh-Hans and every `DiagnosticCode` member has an entry — this prevents the classic half-translated release. Default follows system locale, switchable at runtime from the top bar.

## Screens, in build order

**S1 — Shell + import + report (M11).** One window, top bar: 中/EN · 帮助 · **「没有声音？」** · **「生成诊断包」** · a persistent amber badge 「本程序未经实机验证」 while `profile.verifiedInGame == false`, showing `ProfileVersion` and `ValidatedAgainstGameBuild` on hover.
- *文件与音轨*: drop zone; track `DataGrid` — ☑ / 名称 / 音符数 / 时长 / 音域 / 平均复音 / ★推荐; percussion greyed and unselectable.
- *转换设置*: 移调 spinner + 「自动」 · 移调模式 (保持原调 / 平衡 / 自由 / 手动) · 速度 · 超范围处理 · 时间参数 profile picker — **every timing value renders with its `Provenance` badge and a dotted underline plus tooltip 「此数值未经实测」 when `measured: false`**.
- *演奏性报告*: grade + a horizontal **stacked penalty bar** (丢音 −12 / 八度折叠 −7 / 速度 −3), never a bare number — a bare "78/100" tells the user nothing, the breakdown tells them what to change. Clicking a segment filters the note grid. Below it: the transposition candidates as a radio list showing each one's four tier values, re-running the pipeline on click (tens of ms). Three ceilings plus `EffectiveCeiling` and `MaxSustainableSpeedFactor`.
- *导出*: capability-driven — unsupported targets disabled with the reason, warnings and `ExtraInstructions` surfaced generically, `CumulativeDriftMs` shown.

**S2 — Note editor (M12).** The full editor is a settled requirement (user decision #6) and is **scheduled, not popularity-gated**. `DataGrid` columns `# · mm:ss.mmm · 小节:拍 · 度数 · # · 八度 · 按键 · 修饰键 · 原音 · Δ半音 · 标记`, defaulting to the filter 「只看有问题的音」 (`Alteration != None`). Inline edit of degree / accidental / octave-shift, delete/mute, and `PromoteChordSibling` from a dropdown listing the retained siblings by pitch. Clicking any diagnostic selects its note; clicking a penalty-bar segment filters to the responsible notes. Below: a **read-only** piano-roll strip — grey source rectangles versus coloured emitted ones, with a shaded playable-range band and the chosen transposition drawn as an offset. Deliberately not interactive: the score is monophonic, so it is a list, and a list editor plus a read-only strip carries the information at a fraction of the cost of drag-to-move.

**S3 — Edit journal + `.hsproj` (M12).** An ordered `List<ScoreEdit>` of flat records with a single enum discriminator (no `[JsonDerivedType]` — polymorphism plus source-gen plus AOT discipline is a live pain point), anchored to `SourceIndex` **and** a content fingerprint, never to generated `ScoreNote.Id` (which shifts the moment the transposition changes). The list **is** the undo stack, for free, and it is git-diffable. Save/open `.hsproj` with the profile-snapshot field diff described in the data model.

**S4 — 排练 rehearsal view (M13).** Eight jianpu buttons `1 2 3 4 5 6 7 1̇` plus three mouse lamps 降/半/升, animated at a virtual playhead **driven by the very same `InstrumentSimulator` that the round-trip test asserts against**. So the rehearsal view is a *rendering of a verified invariant* rather than a second implementation that can silently drift — and it is a complete, zero-injection product if Branch A ever turns out to be non-viable. Playhead, progress bar, tempo readout, loop-a-section.

**S5 — 演奏 playback (M14).** Preflight panel showing all six rungs with their verdicts and evidence; 3-2-1 countdown (the user alt-tabs in themselves — we **never** call `SetForegroundWindow`, which is both a fight with the OS and an anti-cheat heuristic); a live trace tail; big 停止 (F7) button; a persistent one-line risk banner on this region only.

**S6 — 自检与诊断 (M14).** The Notepad delivery test with its readback diff; the six-rung decision tree as an interactive flow; 「生成诊断包」; the binding-capture UI; 「导入配置文件」/「粘贴配置文件」/「导出配置文件」 with a validating field diff before accepting; and the **实机验证向导** — a questionnaire, not an auto-prober, because auto-probing presupposes Branch A already works, which is circular.

**First run:** a blocking bilingual disclaimer modal (Chinese primary, English secondary), dismissible only by explicit action, plus the persistent playback banner.
