The instrument is fully chromatic across 38 semitones, so there is no "out of scale" problem — the only two real problems are **which transposition** and **which modifier plan**, and they are coupled. Because the 8 key degrees are pairwise distinct, a modifier state uniquely determines the physical key for any playable pitch, so fingering collapses to a state space derived from the profile (6 states for this instrument) and the joint problem becomes an exact integer Viterbi inside a full sweep of exact-range transpositions. That is the product, and it is 100% provable on a Mac.

Everything else follows from one constraint: the developer can never run the game. So (a) every unverifiable quantity — key bindings, hold-vs-toggle, all timing constants, vendor quirk polarities — is a JSON value with a provenance badge, never a constant; (b) the single `InputTimeline` (absolute int milliseconds) is the only contract both branches consume, and it is validated, golden-filed, hash-stamped and replayed through an independent `InstrumentSimulator` that asserts sounded pitch is *constant across each note's whole span*; (c) the free `windows-2025` GitHub runner is used aggressively to shrink the unverifiable surface to literally one question — does Delta Force accept injected input; (d) the first public artefact is the AutoHotkey exporter, which reaches the game through an injection engine thousands of people have already validated and therefore ships **before** any of the developer's own Windows code exists; (e) one canonical trace writer produces both the golden files and the production run log, so a user's emailed log is directly diffable against CI, and `hsc replay` re-runs their exact session on the Mac.

Three things the judges killed and that this plan does not contain: seam alternation as a feature (it is refuted by the instrument's own algebra — every alternative spelling costs a modifier transition), a weighted-sum objective where mechanical crumbs can silently detune a piece (replaced by a tiered lexicographic objective), and a scheduler that mutates the timeline below the validator (hold caps are a compile-time property of the IR).
